# ExpiryManager — 매장 유통기한 관리

베이커리 매장 공용 기기 1대에서 사용하는 수동 입력 중심 앱입니다. 기존 Wage 저장소와 별도 프로젝트이며, 서버·DB·본사 제품 정보 연동 없이 동작하도록 작성했습니다.

## 실행

1. 이 저장소의 Code → Download ZIP으로 내려받아 압축을 풉니다.
2. 공용 기기의 Chrome 또는 Edge에서 index.html을 엽니다. 별도 설치나 빌드는 없습니다.
3. 계속 같은 경로, 같은 브라우저 프로필에서 사용합니다. 파일 경로를 변경하면 기존 기록이 보이지 않을 수 있습니다.
4. 본격 사용 전 시험 상품을 등록하고, 새로고침 후 유지 여부와 백업·복원을 확인하세요.

현재는 소스 저장 상태이며 웹 주소 배포는 설정하지 않았습니다. 로컬 파일에서의 저장 동작은 브라우저에 따라 달라질 수 있으므로, 안정적인 운영에는 고정 HTTP(S) 주소 사용을 권장합니다. 비공개 저장소의 GitHub Pages 제공 여부는 계정 요금제 확인이 필요합니다.

## 기능

- 상품명·유통기한 필수, 수량·메모 선택 입력
- 기존 상품명 자동완성, 같은 상품 입고 시 이름·메모 재사용
- 날짜가 다른 입고 상품은 별도 기록으로 관리
- 유통기한 오름차순 조회, 상품명·메모 검색
- 기한 경과 / 오늘까지 / 1~3일 이내 필터
- 상품 수정, 판매완료·폐기 처리 및 복구
- JSON 파일 백업·복원: 기존 기록 유지, 같은 ID는 백업 내용으로 갱신
- 모바일·태블릿 대응 화면

수량은 선택 기록이며 일부 판매에 따른 재고 자동 차감은 없습니다. 판매완료·폐기는 해당 입고 기록 전체를 처리합니다. 필요한 경우 수량을 수정하세요.

## 날짜 기준

기기 현지 날짜를 기준으로 날짜 차이를 계산합니다. 전일 이하는 기한 경과, 당일은 오늘까지, 다음날부터 3일 뒤까지 임박으로 분류합니다. 포장에 시각이 표시된 상품의 시간 단위 관리는 포함하지 않았습니다. 처리 내역의 표시 날짜는 저장된 UTC 타임스탬프의 날짜를 사용합니다.

## 저장·백업

브라우저 localStorage의 bakery-expiry-manager-v1 키를 사용합니다. 저장하는 내용은 version, items, lastBackup입니다. 상품에는 id, name, expiry, quantity(null 허용), note, status(active/sold/discarded), createdAt, updatedAt을 기록합니다.

기록은 GitHub로 전송하지 않습니다. 기기·브라우저 간 자동 동기화나 서버 백업은 없습니다. 브라우저 데이터 삭제·시크릿 모드·기기 고장에 대비해 매장 마감 시 백업 파일을 외부 위치에 보관하세요. 백업 생성 표시는 다운로드 완료를 보장하지 않으므로 실제 파일 저장 여부를 확인하세요. 여러 탭의 동시 편집은 피하세요.

앱을 닫은 상태에서 푸시·예약 알림은 제공하지 않습니다. 날짜 경과를 이유로 기록을 자동 삭제하지 않습니다. 저장 오류 시 성공으로 표시하지 않으며, 기존 데이터 해석 오류가 발생하면 덮어쓰기를 막습니다.

## 확인 범위

날짜 유효성·윤년·기한 경계의 분리 로직 9개 사례를 확인했습니다. 실제 기기에서의 화면 조작·새로고침 유지·파일 백업 및 복원 테스트는 아직 수행하지 않았습니다.
